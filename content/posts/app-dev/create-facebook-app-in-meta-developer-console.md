### PART 1 — Create Facebook App in Meta Developer Console

Start by going to [Meta for Developers](https://developers.facebook.com/)

**1. Create a Developer Account**

If this is your first time using Meta for Developers:

- Log in with your Facebook account
- Accept the developer terms and continue

**2. Create a New App**

From the dashboard, click:

**My Apps → Create App**

Choose the app type:

**Consumer**

(or sometimes **Other**, depending on how Meta’s UI looks at the moment)

Then fill in:

- App Name: your_app_name
- Email: your email address

Create the app and continue.

### PART 2 — Add Facebook Login Product

Inside the app dashboard:

- Click Add Product
- Choose Facebook Login
- Select Web Application

This enables OAuth login support for your app.

### PART 3 — Configure OAuth Redirect URL

This is the part that usually causes the most issues, so it’s important to get it right.

**Where does the redirect URL come from?**

In Keycloak, go to:

**Realm → Identity Providers → Facebook**

When you configure the Facebook provider, Keycloak shows you a generated redirect URI.

It usually looks something like this:

```http://localhost:7080/realms/your_app_name/broker/facebook/endpoint```

That URL is:

- generated by Keycloak
- unique per realm
- specific to the Facebook provider

**Add Redirect URI in Meta**    

In the Meta dashboard, go to:

**Facebook Login → Settings**

Under Valid OAuth Redirect URIs, paste the exact URI that Keycloak generated:

```http://127.0.0.1.localtest.me:5173/realms/your_app_name/broker/facebook/endpoint```

Then save the changes.

**Important**

The redirect URI must match exactly.

If there’s even a small mismatch, you’ll run into errors such as:

- ```Invalid redirect_uri```
- ```URL Blocked```
- ```App Misconfigured```
- ```OAuthException```

A missing slash, wrong port, or different hostname is enough to break the login flow.

### PART 4 — Get Client ID and Secret

In the Meta dashboard, open:

**App Settings → Basic**

You’ll find:

| Field      | Meaning             |
| ---------- | ------------------- |
| App ID     | OAuth Client ID     |
| App Secret | OAuth Client Secret |


### PART 5 — Configure Facebook Provider in Keycloak

Now go to the Keycloak Admin Console and open:

**Identity Providers → Facebook**

Fill in the following:

| Keycloak Field | Value                  |
| -------------- | ---------------------- |
| Client ID      | Meta App ID            |
| Client Secret  | Meta App Secret        |
| Default Scopes | `email public_profile` |

** What do those scopes mean?**

| Scope            | Purpose                   |
| ---------------- | ------------------------- |
| `email`          | Access the user’s email   |
| `public_profile` | Basic profile information |

Without the email scope, Facebook may not return the user’s email address.

### PART 6 — Enable Client Authentication

This is usually enabled by default.

Keycloak uses the `client_id` and `client_secret` to securely communicate with Facebook during the OAuth flow.

### PART 7 — Save Provider

Click **Save.**

At this point, Keycloak is ready to handle Facebook login for your application.

### PART 8 — Test the Login Flow

Open your application’s login page.

You should now see a Sign in with Facebook option.

The flow will look like this:

React App
   → Keycloak
   → Facebook
   → Keycloak
   → React App

Your frontend never directly handles Facebook OAuth tokens.

### PART 9 —What Keycloak Does Behind the Scenes

Once the user logs in through Facebook, Keycloak takes over and handles the rest.

It will:

- receive the user details from Facebook
- create an internal Keycloak user
- link the Facebook account to that user
- issue:
    - Access Token
    - Refresh Token
    - ID Token

Your React application only talks to Keycloak, which keeps authentication centralized and much cleaner.

**Example**

Inside Keycloak, you might see something like:

```bash
Users
   christyjohn@gmail.com
```

And under Federated Identity:

```facebook```

Keycloak stores the mapping between the Facebook account and the internal user

### PART 10 — Production Considerations

For local development, localhost URLs are fine.

For production, you should use your real authentication domain instead, for example:

https://auth.your-app.com/realms/vilka/broker/facebook/endpoint

That exact URL must also be added in the Meta dashboard under Valid OAuth Redirect URIs.

### Common Errors

#### 1. Invalid Redirect URI

**Cause:**
The redirect URI in Meta does not exactly match the one generated by Keycloak.

**Fix:**
Copy the URI directly from Keycloak and paste it into Meta without modifying it.

#### 2. App Not Setup

**Cause:**
Your Facebook app is still in development mode.

**Fix:**
Go to:

**App Review → Make App Live**

#### 3. Email Not Returned

**Cause:**
The `email` scope is missing.

**Fix:**
Make sure your scopes include: `email`


### Recommended Authentication Setup for your App

Eventually, your setup could look like this:
| Provider          | Purpose               |
| ----------------- | --------------------- |
| Username/Password | Default login         |
| Facebook          | Social login          |
| Apple             | iOS users             |
| Google            | Android/general users |


Keycloak can unify ALL of them into ONE user system.

### Final Concept to Remember

Your React app should not implement Facebook OAuth directly.

Instead, the flow should always be:

```React → Keycloak → Facebook```

That setup gives you:

- centralized authentication
- unified JWT handling
- single logout support
- easier security management
- provider flexibility
- RBAC support
- MFA support later

That’s one of the biggest reasons teams use Keycloak in the first place.
